# Build a Beginner-Friendly Musical Ear Training Web App

Build a polished, responsive web application for **beginner musicians to learn to identify musical notes by ear**, with a particular focus on guitar players.

The core philosophy of the application is:

> **Do not overwhelm beginners with all 7 or 12 notes at once. Introduce notes progressively, allow the learner to choose exactly which notes they are practicing, train the same note across different octaves/pitches, and gradually transition from isolated notes to real musical contexts and songs.**

The application should feel like a combination of **Duolingo + a musical ear trainer**, with progression, repetition, statistics, difficulty levels, and practical musical application.

---

# 1. Target User

The primary user is a complete beginner who:

* Plays or is learning guitar
* Wants to recognize notes by ear
* Wants to eventually hear a song and figure out its melody on guitar
* Does not yet have strong relative pitch
* Finds traditional ear-training websites overwhelming because they immediately include all 7 or 12 notes
* Wants to start with only two notes, for example:

  * C vs D
  * then C vs D vs E
  * then C/D/E/F
  * etc.

The app should support other instruments eventually, but **guitar should be the primary instrument**.

---

# 2. Core Learning Concept

The application should teach several related skills separately.

### Skill A — Note Identity

Example:

Play either C or D.

Question:

> "Which note did you hear?"

Options:

* C
* D

The user should not see all 12 notes.

The learner controls exactly which notes are currently active.

---

### Skill B — Pitch / Octave Recognition

The same note can occur at different pitches.

For example:

* C2
* C3
* C4
* C5

These are all **C**, but they are different octaves.

The app should explicitly teach:

> "Same note, different octave."

Initially, octave should NOT matter.

For example:

C2 → answer: C

C4 → answer: C

C5 → answer: C

Later, introduce octave recognition as a separate skill.

---

### Skill C — Relative Pitch

Eventually teach:

> "How far apart are these two notes?"

For example:

C → D = Major 2nd

C → E = Major 3rd

C → G = Perfect 5th

This should be introduced only after the user has developed basic note recognition.

---

### Skill D — Scale Degrees

Introduce:

C major:

C = Sa / Do
D = Re
E = Ga
F = Ma
G = Pa
A = Dha
B = Ni

The learner should eventually be able to hear:

> Sa → Ga → Ma → Ga → Re

rather than only thinking in absolute note names.

This is particularly useful for Indian music.

Allow users to switch between:

* Western note names
* Solfège
* Indian sargam

For example:

C = Sa = Do
D = Re = Re
E = Ga = Mi
F = Ma = Fa
G = Pa = Sol
A = Dha = La
B = Ni = Ti

Do not force this terminology on the user; make it configurable.

---

# 3. Progressive Learning System

This is the most important feature.

Never force a beginner to practice all notes.

Create a progression system.

### Stage 1

Two notes:

C vs D

### Stage 2

Three notes:

C vs D vs E

### Stage 3

Four notes:

C vs D vs E vs F

### Stage 4

Five notes:

C vs D vs E vs F vs G

### Stage 5

Six notes:

C through A

### Stage 6

Seven natural notes:

C D E F G A B

### Stage 7

Chromatic notes:

C C# D D# E F F# G G# A A# B

### Stage 8

Different octaves.

### Stage 9

Random notes across multiple octaves.

### Stage 10

Intervals.

### Stage 11

Melodies.

### Stage 12

Real songs.

However, progression should NOT be strictly linear.

Allow users to manually configure the notes they want.

Example:

> Practice Notes

☑ C
☑ D
☐ E
☐ F
☐ G
☐ A
☐ B

The user can therefore create:

> "C vs D training"

whenever they want.

# 4. Difficulty Levels

Each exercise should have difficulty settings.

## Beginner

* 2 notes
* Same octave
* Long notes
* Clear instrument sound
* No background music
* Unlimited time

Example:

🎵 C

Options:

C | D

---

## Easy

* 2–3 notes
* Different octaves
* Slightly shorter notes

---

## Medium

* 3–5 notes
* Different octaves
* Random order
* Different note durations

---

## Hard

* 7 natural notes
* Multiple octaves
* Short notes
* Random instrument sounds

---

## Expert

* 12 chromatic notes
* Multiple octaves
* Very short notes
* Similar neighboring pitches
* Notes embedded inside musical phrases

# 10. Octave Training

Once the user is comfortable identifying note names, introduce octave recognition.

Example:

Play C3.

Question:

> Which C did you hear?

Options:

C3
C4
C5

Use visual indicators such as:

Low / Middle / High initially.

Do not assume beginners understand scientific pitch notation.

First teach:

> Low C
> Middle C
> High C

Then optionally display:

> C3 / C4 / C5

---

# 11. "Find It On Guitar" Mode

Create another exercise type.

The app plays:

🎵 G

Then asks:

> Find this note on your guitar.

Show a fretboard.

The user clicks a fret.

Example:

6th string → 3rd fret

App responds:

> Correct!

or:

> That's G#.

This connects hearing with physical guitar knowledge.

Allow multiple correct positions.

Example:

If the target is G3, several guitar positions may contain G3.

Explain why.

---

# 12. Ear → Voice → Guitar Exercise

Create a special exercise called:

## "Hear → Sing → Find"

Step 1:

Play a note.

Step 2:

Ask the user to sing/hum the note.

Step 3:

Ask them to find it on guitar.

The app cannot perfectly judge singing initially, so make the singing step optional.

Potential future feature:

Use microphone pitch detection to determine whether the user is singing approximately the correct pitch.

Display:

> Target: G4
> Your pitch: G4

or:

> Try singing slightly higher.

This feature should be modular and optional.

---

# 13. Relative Pitch Training

After note recognition becomes comfortable, introduce interval training.

Start with:

* Same note
* Minor 2nd
* Major 2nd
* Minor 3rd
* Major 3rd
* Perfect 4th
* Perfect 5th
* Octave

Do NOT introduce every interval simultaneously.

Progress:

### Level 1

Same vs different

### Level 2

Unison vs Major 2nd

### Level 3

Major 2nd vs Major 3rd

### Level 4

Major 2nd / Major 3rd / Perfect 4th

etc.

Use musical examples and memorable references where appropriate.

---

# 14. Melody Training

Once basic note recognition is established, introduce short melodies.

Example:

Play:

C → D → E → D

Ask the user to reproduce it.

Possible modes:

### Identify

"What was the first note?"

### Direction

"Did the melody go higher or lower?"

### Note sequence

"Which sequence did you hear?"

C D E D

C E D C

D E F E

### Reproduce

Show a virtual guitar/piano keyboard and let the user reproduce the melody.

---

# 15. Song Mode

This is the ultimate goal.

Create a section:

# Learn From Songs

Use simple melodies first.

Examples:

* Happy Birthday
* Twinkle Twinkle Little Star
* Ode to Joy
* simple folk melodies
* simple Indian melodies

Eventually add popular songs, but do not ship copyrighted melody transcriptions unless legally permitted.

The app can instead allow the user to enter/import their own songs or use public-domain melodies.

The lesson structure:

### Step 1

Listen to the melody.

### Step 2

Find the starting note.

### Step 3

Identify whether the next note goes:

* Higher
* Lower
* Same

### Step 4

Identify the interval.

### Step 5

Identify the exact note.

### Step 6

Find the note on guitar.

This should teach the actual skill of figuring songs out by ear.

# 19. Intelligent Adaptive Difficulty

The application should automatically adapt.

Example:

If:

C = 95%
D = 92%

Then suggest:

> "You're ready to add E."

If:

C = 96%
D = 94%
E = 58%

Then recommend:

> "Keep practicing C, D and E."

Do not add new notes just because the user completed a fixed number of questions.

Use accuracy thresholds.

Example:

* <60% → stay at current level
* 60–80% → continue
* > 80% → recommend next note
* > 90% → allow next difficulty

Make thresholds configurable.

# 24. Frequency / Note Data Model

Represent notes using:

* Note name
* Pitch class
* Octave
* Frequency
* MIDI note number

Example:

C4:

note = C
pitchClass = 0
octave = 4
midi = 60
frequency ≈ 261.63 Hz

C5:

note = C
pitchClass = 0
octave = 5
midi = 72
frequency ≈ 523.25 Hz

This distinction is critical.

The application should treat:

C4 and C5 as:

> same pitch class

but:

> different absolute pitches.

# 37. Important Educational Principle

Do not teach the user to memorize the visual appearance of notes.

The main skill is:

> **Sound → Brain → Note**

not:

> Picture → Note

The fretboard is used later to establish:

> **Sound → Note → Guitar position**

Similarly, do not make the user depend on a reference note forever.

Initially, a reference C/Sa can be useful.

Eventually, exercises should randomly start in different keys and registers so the learner develops genuine relative pitch.

Eventually create a feature called:

# Song Detective

### 1. Find Sa

### 2. Find the first note

### 3. Is the next note higher or lower?

### 4. How far did it move?

### 5. Identify the note

### 6. Find it on guitar

### 7. Repeat

The goal is to turn:

> "I like this melody but I don't know the notes."

into:

> "I can figure out the melody myself."

This should be the long-term direction of the product.

# 40. Final Product Goal

The application should ultimately train the user through this progression:

**Hear C/D**

↓

**Hear C/D/E**

↓

**Recognize all natural notes**

↓

**Recognize the same note in different octaves**

↓

**Understand higher/lower pitch**

↓

**Find the note on guitar**

↓

**Recognize intervals**

↓

**Recognize Sa/Re/Ga/Ma**

↓

**Recognize short melodies**

↓

**Transcribe melodies**

↓

**Hear a real song**

↓

**Figure out its melody on guitar by ear**

The application should make this progression feel natural and achievable rather than overwhelming.

Build the MVP first, but architect the code so all later stages can be added without rewriting the core audio, note, fretboard, and training systems.
